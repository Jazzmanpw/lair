# Running Mode Planning

Start here when returning to Running Mode work.

## Workflow

1. If there are uncommitted changes, find the last relevant agent session and recall what was done before proceeding. Refresh the big picture below to stay on track.
2. If the repository is clean, refer to the best next move. Start a new session, scan the design memory system for relevant context, and work on the task.
3. Once the task is done, think about the next things before committing:
   - What should be the next best move?
   - Should the big picture shift?
   - What should be updated in the design memory based on the completed work?
   - Does anything belong in the R2 framing, or has the work produced a durable finding instead?
   - How should the previous step be described so that it helps move the project forward? If there is nothing especially valuable to preserve, add a short description of the completed task.

When moving prototypes between active and archived status, use the [Prototype Lifecycle](./prototype-lifecycle.md).

## The Big Picture

Running Mode Layout R1 is complete. Its FPO-only prototypes were useful for exploring broad spatial strategies, but they also exposed how little was known about the internal structure of the content zones. The next useful step is to understand what those components contain, how their information is grouped, and how much width and height they need before another full-screen layout iteration.

The component studies should feed [Running Mode Layout R2 framing](./r2-framing.md). R2 will use a smaller known set of layout directions, preserve a couple of slots for ideas discovered during component work, and test the strongest directions with better structural evidence.

`R[n]` means round number `n` of prototyping for one named surface, not a project-wide iteration. Layout R1 generated component-internal studies that feed Layout R2; those side studies do not use round notation unless that particular component later needs another explicit prototyping round.

Component-study notes live beside their Storybook artifacts. The participant and roster note is at [`libs/ui/src/running-mode/roster/README.md`](../../../libs/ui/src/running-mode/roster/README.md).

## Design Memory

- [Findings](./findings.md) are durable records of what was learned and why it matters.
- [Hypotheses](./hypotheses.md) are shaped answers worth testing next.
- [Open questions](./open-questions.md) are unresolved prompts and task seeds.
- [Vocabulary](./vocabulary.md) defines shared Running Mode terms.

The files deliberately avoid topic grouping beyond their Running Mode scope. Every Running Mode task must scan findings, hypotheses, and open questions for relevant context and for entries it may resolve.
